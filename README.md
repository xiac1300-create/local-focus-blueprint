# 本地专注工具：AI 重建蓝图

把这份设计交给自己的 AI 编程工具，生成可检查、可修改的安卓应用。仓库分享功能原理、权限边界和验收方法，暂不分发 APK、原应用源码或任何个人使用记录。

这是供重建使用的说明草案。你可以调整功能、界面、应用名称和规则；每个人生成的软件都需要独立验证。

## 怎样让自己的 AI 使用

需要能读取文件、修改项目并运行构建工具的 AI 编程环境。普通聊天工具也能协助设计，但未必能直接生成可安装 APK。Android SDK、构建工具和签名由使用者自己的环境提供。

1. 下载或复制本仓库。
2. 让 AI 先阅读下方提示中指定的文件。支持 Skill 的工具也可以按其安装说明导入 `skills/build-focus-app` 整个文件夹。
3. 先生成基础统计版本，检查源码和权限，再决定是否加入应用锁。
4. 在自己的设备上按验收案例测试，明确授权后再开启手机上的特殊访问权限。

可以把下面这段作为开始提示：

> 请阅读 `skills/build-focus-app/SKILL.md` 及其引用文档，为我重建一个安卓本地专注工具。我希望先完成基础应用用时统计；确认结果后再决定加入哪些限制功能。请使用独立项目、应用标识和签名，交付完整源码和构建说明。说明每项权限实际做什么、拒绝后哪些功能不可用。不要增加联网、广告或后台上传，也不要替我开启手机权限。先检查我的开发环境，只问缺失且会改变实现的信息。

## 怎样理解权限与隐私

自己生成、源码公开或没有网络权限，都不能单独证明应用安全。最终要检查实际生成的代码、依赖、安装包权限和运行行为。无障碍等系统权限范围较大，生成应用即使只打算读取包名，也必须让使用者了解授权范围。

默认记录仅留在本机，拒绝某项特殊访问时应保留能运行的基础功能。导出的应用名称、包名和时间记录仍可能反映个人习惯，分享前需要自行查看。Skill 不会代替系统授权，也不具有读取手机记录的独立能力。

不要把普通应用覆盖层描述成不可绕过的系统冻结；暂停监测、撤权或卸载会解除限制。不同系统的后台与自由浮窗行为需分别验证。
