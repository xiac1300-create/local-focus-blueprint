# 权限、数据与验证

这份表描述重建应用应遵守的设计，不代表任意 AI 生成的安装包已经符合它。每次生成后都要对最终源码、依赖、合并后的权限清单和运行行为重新核对。

## 功能与授权分开

| 能力 | 为何需要、实现只使用什么 | 用户选择与拒绝后的表现 |
| --- | --- | --- |
| 使用情况访问 | 查询应用包名、前后台事件与时间，重建基础用时；可读到系统仍保留的近期历史 | 经系统“使用情况访问”设置授权；不授权时不假装已有完整统计，保留已有本地数据 |
| 窗口识别（无障碍服务） | 确认窗口所属应用、焦点、画中画和位置；系统授权能力包含读取窗口结构，代码仅提取包名与窗口属性，不读取节点正文、不截图、不自动点击 | 使用者明确接受后手动启用；拒绝或撤回时显示多窗口识别／拦截降级 |
| 显示在其他应用上层 | 显示普通覆盖拦截界面 | 由使用者到系统设置启用；不授权时普通覆盖层不可用。无障碍覆盖层是另一机制，是否可用取决于服务状态 |
| 通知访问（可选播放状态） | 通过媒体会话获取包名和正在播放状态；不要读取、存储或上传通知正文 | 系统授权范围比播放状态更广，须单独说明并允许跳过；拒绝时不记录后台媒体 |
| 发送本应用通知 | 展示监测状态和暂停入口；Android 13及以上需处理通知授权 | 与“读取其他应用的通知”不同；不能把发送通知的允许误当成通知访问已开启 |
| 前台服务 | 在使用者启动后持续运行本地监测，按目标系统规则声明所需服务类型 | 前台服务不是读取其他应用内容的授权；提供暂停入口，并正确处理系统终止 |
| 应用图标和名称、文件导出 | 查询符合产品范围的可启动应用；主动将报告交给系统保存或分享界面 | 不为此默认申请全盘存储或全部包查询；保存位置、接收方由使用者选择 |

`PACKAGE_USAGE_STATS` 的清单声明本身不足以授予使用情况访问。[Android 官方说明](https://developer.android.com/reference/android/app/usage/UsageStatsManager)要求经系统设置开放访问。

无障碍与通知监听服务使用的 `BIND_ACCESSIBILITY_SERVICE`、`BIND_NOTIFICATION_LISTENER_SERVICE` 是服务声明的绑定保护，不应写成向用户弹窗申请的普通运行时权限。各自的系统启用入口也不同。可查 [AccessibilityService](https://developer.android.com/guide/topics/ui/accessibility/service)、[NotificationListenerService](https://developer.android.com/reference/android/service/notification/NotificationListenerService) 及 [悬浮窗授权设置](https://developer.android.com/reference/android/provider/Settings#ACTION_MANAGE_OVERLAY_PERMISSION)。

## 数据流目标

允许保存：应用标识、开始／结束时间、前台／可见／焦点／画中画／媒体等观察通道、来源、观察中断、使用者主动设置的规则。选定应用名称与图标用于展示。

默认不采集：聊天正文、输入内容、通知正文、页面文字、截图、音频、视频、联系人、位置、账号凭据。也不加互联网权限、遥测、广告或自动上传代码。

本机记录本身可以反映作息和习惯，不能宣称“没有隐私数据”。使用应用私有存储；没有实现额外应用层加密时，不宣称数据库已加密。说明备份设置和数据保留策略，日志不输出私人内容。

暂停监测、系统撤权与清空数据是三个不同动作。清空本应用记录不删除系统使用历史，恢复同步可能再次导入近期历史。已另存或分享的文件也不会随本地清空而删除。

导出前让使用者查看范围并主动选接收方。使用受限的只读临时授权；不提供任意路径访问，不向其他应用公开整个数据库。接收方可能联网，纯本地应用的承诺不延伸到接收方。

## 用合成数据验证

以下案例按实际启用功能选择；基础统计版本不需要先实现完整应用锁。所有结果须标明模拟器、系统版本和真实完成范围。

| 场景 | 应观察到的结果 |
| --- | --- |
| 首次打开，不授权任何特殊访问 | 说明缺失能力；不悄悄启用监测或声称有完整历史 |
| 不开通知访问，只启用基础记录 | 基础记录仍工作；后台媒体显示未启用／未知 |
| 分别撤回用量访问、窗口识别、通知访问 | 状态真实降级；不崩溃，不继续显示“全部正常” |
| 应用A先打开，再开始学习，进入最近任务切回A | 名单外A仍被复核；不因使用区间开始时间较早而漏拦 |
| 选择3个普通应用，再选择第4个 | 拒绝新增且保留原名单；本应用与必要系统入口不占名额 |
| 学习期间尝试改普通名单、用临时放行访问名单外应用 | 名单不扩展；明确结束学习后才允许修改 |
| 餐外把用餐应用／陪用应用放进普通名单或开启临时放行 | 餐外仍锁定两类用餐成员 |
| 点击吃饭后取消二次确认 | 未开启、未扣次数 |
| 成功开启，重复点击，再提前结束 | 一次计数、期限不延长、提前结束不返还 |
| 当天成功开启两次，重启进程再尝试第三次 | 次数保留，第三次拒绝；目标仍锁定 |
| 熄屏跨过到期点，再唤醒 | 一小时按连续经过时间计算，唤醒后复核锁定 |
| 次日、日期回退、系统重启、时间异常 | 按规格重置新日额度；回退不送新次数；异常不延长当前放行 |
| A为主窗口、B为画中画，交换焦点 | 记录并行、同应用去重；无焦点PiP不凭空增加切换 |
| 受限小窗停留在本应用／系统设置上方 | 有实现局部遮挡时只覆盖已识别的小窗，保留救援页面可用区域；普通应用上方仍按规则拦截 |
| 停止服务、后台清理、系统休眠或窗口归属未知 | 不凭空补录未知时长，不假装具备不可绕过锁定 |
| 暂停、清空、主动导出 | 各自只执行说明中的动作，报告接收方仅获得选中报告的只读访问 |

还需检查最终安装包与源码：没有联网权限、无隐含上传依赖、无页面正文／通知正文／截图采集、没有可公开访问的记录提供器；导出前没有将记录交给其他应用。权限清单与静态搜索只是证据的一部分，仍需动态观察和测试。

无障碍服务能读取窗口结构并不意味着能识别所有厂商自由浮窗。覆盖层也不会自动终止第三方进程或暂停音频。模拟器通过不能直接代表每款真机通过。

## 交给读者的验证结论

每次交付列清：生成了哪些源文件、是否成功构建、测试了哪些用例、在哪些设备完成、哪些权限实际开启、还有哪些限制。不要沿用蓝图作者或其他生成项目的测试数字作为新应用证明。

公开分享仅使用合成示例，不包含个人 CSV、数据库、截图、设备日志、导出包、账号配置、签名私钥或原始对话。新的应用使用自己的签名，私钥由使用者自行妥善备份。
