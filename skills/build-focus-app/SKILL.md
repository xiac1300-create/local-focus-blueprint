# 重建安卓本地专注工具

帮助使用者生成自己能检查、编译和修改的项目。交付完整源文件、构建说明和真实验证状态；不把这份蓝图、原作者的测试或一次成功编译当成生成应用已经安全可用的证明。

## 先定位目标

- 已有项目时先检查其结构和权限；新项目使用独立工作目录、自己的应用标识和签名。不要从其他项目复制密钥、数据或账号配置。
- 仅询问会改变实现的信息：安卓版本、想先做记录还是限制、是否接受窗口识别、现有构建环境。已经提供的信息不重复问。
- 默认纯本地、无账号、无上传；先做基础用时统计，再按使用者需要加窗口识别和应用锁。不要一次开启所有特殊访问权限。
- 实现产品规则前读 [产品规格](references/product-spec.md)；设计授权界面、数据存储及验收前读 [权限与验证](references/privacy-and-verification.md)。

## 实现时保留的边界

1. 只记录已启用功能需要的包名、起止时间、窗口状态和观察来源。窗口识别可需要读取窗口结构，但实现只取归属和状态，不遍历正文，不截图，不模拟操作第三方应用。说明权限能力范围比实际使用范围更宽。
2. 默认不声明网络权限，不加遥测、广告、崩溃上传或远程分析依赖。导出由使用者主动选择文件或接收方；使用统计本身也是敏感记录。
3. 所有手机端特殊访问权限由使用者查看说明后在系统页面开启。交付构建产物不代表授权安装、连接手机、替用户开启权限或上传到外部服务。
4. 应用锁是可撤回的覆盖拦截。保留暂停、撤权、卸载及必要系统入口；不承诺阻止进程启动、停止后台音频或覆盖全部厂商浮窗。
5. 当前应用按真实恢复事件和当前窗口识别；不要拿旧使用片段的开始时间、旧窗口ID归属或本应用曾处前台的标记作放行依据。
6. 名单与用餐规则优先于普通临时放行。默认用餐规则每天最多成功开启2次，每次最长1小时，并经再次确认；仅成功开启才扣次数，提前结束不返还，重复请求不续时。次数和期限一起持久保存。
7. 同一应用的重叠区间去重，不同可见应用保留并行。桌面、未知、后台媒体分别表达；无法观察的时间不推定为使用或睡眠。

## 分阶段交付

选择适合现有项目的 Android 原生技术栈和本地存储。以目标 SDK 的官方文档及项目已安装依赖核对接口；不要依赖本蓝图固定的旧版本或他人的 SDK 下载目录。

每阶段完成后先验证再扩大范围：基础记录与汇总 → 可选分屏／画中画 → 自愿应用锁与用餐规则 → 本地分析和主动导出。使用者只需要其中一部分时停在相应阶段。

测试用合成数据与隔离模拟器。真机安装、敏感授权和会消耗真实每日次数的验证，需要使用者知情参与。对后台切回、计时持久化和撤权等关键行为按引用文档验收，不以仅检查界面文案代替功能测试。

交付时区分已编译、已在模拟器验证、已在某款真机验证及尚未确认的范围。列明实际权限、数据去向、缺失功能与签名备份位置。没有 Android 构建环境时交付源码与可运行的构建步骤，明确 APK 尚未生成；不要伪造下载链接或测试结果。
